## 1. Charter — what agy is

- **agy is the primary agent's assistant**, not the user's (user's words: "its your assistant
  more than mine, even if i am still human in the loop"). Role: second pair of eyes for
  cross-examining design intent, adjutant/notetaker minting briefs from outlines. It is
  _expected to talk back_ and expose gaps, not to rubber-stamp.
- This is a **sanctioned exception** to the global no-subagent rule. The subagent ban is
  Claude-provider-specific and temporary (token economics); para-agent workers are the intended
  worker tier, with local gguf models as the durable substitute once wiring/governance exist.
- agy runs as a **standing pane**, not per-task spawns: shell pane `agy` in psmux session
  `agent-agy`, cwd = repo root.

## 2. Working mechanics — the established turn pattern

The pattern that has proven reliable, end to end:

1. **Prompt as file, passed as argument.** Write the turn's prompt to
   `C:\Users\azrie\.para-agent\journals\streams\agy\`, then drive the pane with `run`:
   `claude.exe -p (Get-Content <promptfile> -Raw) --allowedTools Read Grep Glob --output-format json`.
   Do NOT pipe the prompt on stdin (see lesson L2).
2. **Parse the JSON receipt** for `SESSION_ID` / `COST_USD` / `TURNS`; use
   `--resume <session_id>` for multi-lane continuity within one engagement.
3. **Read-only tool grant by default** (Read/Grep/Glob) for reviewer turns; grant Write only
   for deposit turns where agy writes its own report file.
4. **Generous timeouts.** Real turns run 6–13 minutes. The working detach pattern:
   `run` with timeoutMs≈5s so the command keeps running past the returned turn, then poll
   `log` (outcome field) or watch for the deposit file to appear.
5. **Redirect output to files** (`1>`/`2>`) when the artifact matters — keeps the report
   byte-exact and immune to pane wrapping.
6. **Journals survive session kill** (verified). History stays fetchable by stream name via
   `log`/`body`, so a killed pane does not lose the record.

## 4. Operational lessons (the digest)

**L1 — Backend availability.** gemini CLI is NOT installed on this machine (an early assumption
that agy could run on it was wrong). As of 2026-08-13, `claude` 2.1.226 resolves on the pane
PATH (the Store install refreshed it); full path `C:\Users\azrie\.local\bin\claude.exe` remains
the fallback when PATH is stale.

**L2 — Stdin pipe dies in the npm shim.** `Get-Content -Raw file | claude -p` fails with
"Input must be provided either through stdin or as a prompt argument." Always pass the prompt
AS an argument: `claude -p (Get-Content <file> -Raw)`, or a one-line prompt telling claude to
Read a brief file.

**L3 — Don't spawn fresh sessions with a program command.** Spawning a NEW para-agent session
with a program command died instantly — the psmux server didn't hold the session. Drive the
STANDING `agent-agy` shell pane with `run` instead.

**L4 — `wait until:pattern` is unusable for headless turns.** Two failure modes compound:
stale screen content from _prior_ turns matches the pattern immediately, and headless claude
prints nothing until completion so `stable` fires instantly. The workable substitute is the
short-timeout `run` + poll `log` / watch-for-deposit-file pattern (§2.4).

**L5 — Write-granted turns front-load the file, not stdout.** When agy has Write, it may print
only a short stdout summary and put the full payload in the deposit file. Read the file; skip
the journal body.

**L6 — Redirects beat pane scraping.** `1>`/`2>` to files keeps reports byte-exact and
pane-wrap-proof; the pane screen is a lossy view.

**L7 — Journal durability is real.** Verified that journals survive killing the session;
history remains fetchable by stream name. This makes the standing-pane pattern safe to reset.

**L8 — Resume-chain lanes compose.** A two-lane brief driven through `--resume` on one session
produced genuine cross-lane reconciliation (lane B evidence revising lane A severities), not
just two disjoint reports. Worth repeating as a standard shape for larger reviews.

**L9 — Denial resilience.** With Bash denied, agy degraded gracefully to grep sampling rather
than stalling. Restrictive tool grants are cheap insurance and don't wreck output quality.

## 5. Triage doctrine — agy output is provisional until checked

Standing rule: **triage agy output before relaying it** — verify-or-probe every load-bearing
claim. The track record justifies both halves:

- _Why it usually pays to trust:_ two engagements with 100% of spot-checked claims exact.
- _Why triage is still mandatory:_ concrete misses on record —
  - agy misread one compressed prompt point (inline slices) — over-compressed briefs are a
    known failure input; write prompts at normal verbosity.
  - Procurement review: one claim **refuted** on triage (`_is_reparse` "latent bug" — the
    jsonl_engine `follow_symlinks=False` stats + `O_NOFOLLOW` opens are exactly the upstream
    guard agy hypothesized but didn't find), one risk-phrase **overstated** (empty
    `allowed_hosts` — the guard exists, it's merely untested), and one question settled by the
    primary's **empirical probe** rather than argument (pinned parent does not block child
    rename, so the disputed test was healthy).
- Pattern in the misses: agy's failure mode is _unfound context_, not fabrication — it flags a
  plausible gap it couldn't locate the guard for. Triage by locating the guard (or probing
  empirically) resolves these quickly.

## 6. Friction points → candidate project updates

These are the observed rough edges, phrased as things the para-agent project could address
(decisions are the user's):

1. **Headless-turn completion signaling.** The biggest workflow gap: `wait until:pattern` is
   structurally wrong for headless runs (L4), so the primary polls `log` or watches the
   filesystem. A first-class "wait for command exit / new-output-since-turn-start" primitive
   would remove the stale-screen and instant-`stable` traps.
2. **Fresh-session spawn with a program command** dies instantly (L3). Either fix session
   holding for program-spawns or document standing-pane-only as the supported mode.
3. **Prompt delivery.** The stdin path into the npm shim is broken (L2); everything routes
   through prompt-file-as-argument. If the MCP grew a "run with prompt file" convenience (or
   fixed stdin plumbing), the per-turn ceremony shrinks.
4. **Receipt capture.** Parsing SESSION_ID/COST/TURNS out of pane JSON works but is scrape-y;
   a structured receipt surface (per-turn metadata via the journal) would make the resume chain
   and cost ledger robust.
5. **Backend abstraction.** The gemini assumption failure (L1) plus the standing local-gguf
   worker-tier direction both point at making the backend explicit/configurable per stream,
   with a probe for what's actually installed.
6. **Output-artifact convention.** The redirect-to-file + Write-granted-deposit patterns (L5,
   L6) evolved ad hoc; a blessed "deposit path" convention per turn would let tooling find the
   artifact without watching the filesystem.
